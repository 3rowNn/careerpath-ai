# CareerPath AI — ชุด Prompt ปรับ UI/UX (ฉบับเข้ากับโปรเจกต์)

ดัดแปลงจากชุด "AI Career Matching + Skill Gap Analyzer" 8 prompt ให้เข้ากับโปรเจกต์นี้
**เป้าหมาย:** เว็บดูเป็นผลิตภัณฑ์จริง สวย ใช้ง่าย โดย **ไม่แตะโมเดล ML และไม่เปลี่ยนสิ่งที่ LLM ทำ**

## วิธีใช้
1. ใช้ทีละ prompt ต่อ 1 รอบงาน ตามลำดับที่แนะนำด้านล่าง ไม่ต้องวางทั้งชุดครั้งเดียว
2. **ทุก prompt ต้องแปะ "P00 กฎร่วม" ไว้ด้านบน** (หรือบอกว่า "ทำตาม P00 ใน docs/UI_PROMPTS.md")
3. จบแต่ละ prompt ให้รัน `cd frontend && npm run build` และ `cd backend && .venv/bin/python -m pytest -q` ต้องผ่านทั้งคู่

| ลำดับ | Prompt | แตะ backend ไหม | ขนาดงาน |
|---|---|---|---|
| 1 | P01 Design system | ไม่ | กลาง |
| 2 | P02 Landing (Home) | ไม่ | กลาง |
| 3 | P06 Skill Gap | ไม่ | กลาง |
| 4 | P05 Careers + รายละเอียดอาชีพ | เพิ่ม endpoint อ่านข้อมูล 1 ตัว | ใหญ่ |
| 5 | P08 Career Explorer + Dashboard + Polish | ใช้ endpoint จาก P05 | ใหญ่ |
| 6 | P04 แบบประเมิน (UX เท่านั้น) | ไม่ | กลาง |
| 7 | P07 Roadmap | ไม่ (ช่วงแรก) | กลาง |
| 8 | P03 Auth + Profile จริง | ใช่ — ระยะ 3 (PostgreSQL + JWT) | ใหญ่มาก |

> ส่วน LLM (AI Advisor) ไม่อยู่ในชุดนี้ ชุดนี้แค่จัดหน้าตาให้พร้อมรับ ส่วนการเชื่อม LLM จริงทำแยกในระยะ 3

## P00 — กฎร่วม (แปะไว้บนทุก prompt)

```
คุณคือ Senior Product Designer + Frontend Engineer ที่ทำงานกับโปรเจกต์ CareerPath AI ที่มีอยู่แล้ว
อ่าน CLAUDE.md และโค้ดที่เกี่ยวข้องก่อน แล้วสรุปแผนสั้น ๆ ก่อนแก้ไฟล์ใหญ่ ห้ามเขียนแอปใหม่ทั้งหมด

โปรเจกต์นี้คืออะไร
- เว็บแนะนำอาชีพสำหรับ "คนที่ยังไม่มีทิศทาง" — เรียนจบแล้วยังไม่มีงาน ไม่รู้ว่าเก่งอะไร ไม่รู้ว่าอยากเป็นอะไร
  ไม่ใช่เครื่องมือของนักศึกษา IT · ทุกสายอาชีพสำคัญเท่ากัน (พยาบาล ช่าง เชฟ ครู คนขับรถ = สาย IT)
- จุดเด่นคือ ML ไม่ใช่ LLM: Ensemble (① Cosine + ②a MLP) จัดอันดับ 910 อาชีพ O*NET, ②b kNN ทาย 22 กลุ่มอาชีพ,
  ③ K-Means หาอาชีพใกล้เคียง, Skill Priority จัดลำดับทักษะที่ขาด · LLM (AI Advisor) แค่อธิบายผลของ ML

ห้ามแตะ (ML / ข้อมูล)
- ทุกไฟล์ใน datasets/ (รวม datasets/ml/predict.py, output/, *.joblib, model_config.json)
- จำนวน ข้อความ และลำดับคำถาม 76 ข้อใน frontend/src/data/questions.json และสูตรแปลงคำตอบ 1–5 → 0–100 ใน api/client.ts
- สูตรคะแนน การจัดอันดับ ความมั่นใจ และ Skill Priority ที่ backend ส่งมา — frontend แสดงผลเท่านั้น ห้ามคำนวณคะแนนเอง
- backend/requirements.txt (scikit-learn==1.9.1 ตรึงไว้)
เพิ่ม endpoint ใหม่ได้เฉพาะแบบ "อ่านข้อมูลที่มีอยู่แล้ว" และต้องมีเทสต์ใน backend/tests/test_api.py

ห้ามแต่งข้อมูล
- ไม่มีข้อมูลเงินเดือน ความต้องการตลาด วุฒิการศึกษาที่ต้องใช้ ใน dataset เรา → ห้ามแสดงตัวเลขพวกนี้ ห้ามใส่ตัวอย่างปลอม
  ถ้าดีไซน์ต้องมีช่องนั้น ให้เขียนว่า "ยังไม่มีข้อมูล" หรือตัดออก
- ห้ามแสดง "Match 92%" — คะแนน Ensemble ไม่ใช่เปอร์เซ็นต์ความเหมาะ ใช้ของที่มีจริง:
  อันดับ, "ทักษะครอบคลุม %" (skill_coverage_percent), ระดับความมั่นใจ (confidence) และคำอธิบายรายคำถาม (explain)
- ความแม่นของโมเดลต้องพูดตามจริงเสมอ: "ทดสอบกับผู้ใช้จำลอง" ไม่ใช่ "แม่นยำ 83%" เฉย ๆ
- ชื่ออาชีพไทยแปลโดย Claude (ไม่ใช่ชื่อทางการ) — ใช้ thaiTitle() จาก api/client.ts จุดเดียว
- โหมดตัวอย่าง (ไม่ตั้ง VITE_API_URL) ต้องยังใช้ได้ และต้องมี SampleBanner บอกว่าเป็นข้อมูลตัวอย่าง

ดีไซน์ที่ตัดสินใจแล้ว (ห้ามเปลี่ยน)
- Stack: React 19 + Vite + TypeScript + Tailwind v4 + TanStack Query + ECharts (ไม่ใช่ Next.js/Recharts)
- สี/ฟอนต์จาก token ใน frontend/src/index.css: primary #2747D0, ink #111827, page #F6F7F9, good/warn
  ฟอนต์ IBM Plex Sans Thai · ห้ามใส่สี hex ตรง ๆ ในคอมโพเนนต์ ให้เพิ่ม token แทน
- UI ภาษาไทยทั้งหมด (ศัพท์เทคนิคอย่าง Skill Gap, Roadmap, AI Advisor ใช้อังกฤษได้)
- เมนูหลักคงเดิม 8 หน้า: หน้าแรก · Dashboard · แบบประเมิน · อาชีพที่แนะนำ · อาชีพที่อยากเป็น · Skill Gap · Roadmap · AI Advisor
  (เพิ่ม Career Explorer ได้ตาม P08) · ห้ามเอา AI Advisor ออกจากเมนูหลัก · ห้ามทำหน้า What-if / Model Lab กลับมา
- ดีไซน์ต้นแบบ: Claude Design canvas https://claude.ai/artifact/Mprg12F9CWzk7FEJjipbFr

คุณภาพ
- ใช้คอมโพเนนต์ใน components/ui.tsx, charts.tsx, icons.tsx ก่อน ถ้าต้องสร้างใหม่ให้ใส่ที่นั่นให้ใช้ซ้ำได้
- Responsive 360px → 1440px ไม่มี scroll แนวนอน · ปุ่ม/ลิงก์สูง ≥ 44px · มี focus-visible · คอนทราสต์ผ่าน WCAG AA
- ทุกหน้าที่เรียก API มี loading / error / empty state
- เคารพ prefers-reduced-motion · animation สั้น (150–250ms) ไม่เด้งเกิน
- จบงานต้อง npm run build ผ่าน และ pytest ผ่าน แล้วสรุปว่าแก้ไฟล์อะไร
```

## P01 — Design system (ขัดเกลาของเดิม ไม่ใช่เปลี่ยนใหม่)

```
[P00]

งาน: ยกระดับ design system ที่มีอยู่ให้ดูเป็น SaaS ระดับมืออาชีพ โดยคงสี/ฟอนต์เดิม

1. ตรวจทุกหน้าใน src/pages/ แล้วทำรายการความไม่สม่ำเสมอ: ระยะห่าง ขนาดหัวข้อ มุมโค้ง เงา ปุ่ม การ์ด สีที่ hardcode
2. เพิ่ม token ใน index.css (@theme): สเกลเงา 3 ระดับ (sm/md/lg แบบนุ่ม), radius 3 ระดับ, สเกลตัวอักษร
   (display/h1/h2/h3/body/small), สีเสริมสำหรับ chart (ไล่จาก primary) และ gradient อ่อน ๆ จาก primary-soft

   Card (มี/ไม่มี hover), Badge, Tabs, Skeleton (ใช้แทน Spinner ในการ์ด), EmptyState (ไอคอน + ข้อความ + ปุ่ม),
   ErrorState (ข้อความ + ปุ่มลองใหม่), Tooltip แบบง่าย

5. ใช้คอมโพเนนต์ใหม่แทนของเดิมทีละหน้า โดยไม่เปลี่ยน logic หรือข้อมูลที่แสดง

ส่งมอบ: รายการ token และคอมโพเนนต์ที่เพิ่ม + ภาพรวมว่าแต่ละหน้าเปลี่ยนอะไร
```

## P02 — หน้าแรก (Landing — src/pages/Home.tsx)

```
[P00]

งาน: ทำหน้า Home ใหม่ให้เป็น Landing page ที่สวยและสื่อสารกับ "คนที่ยังไม่รู้ว่าตัวเองเหมาะกับอะไร"

โทนข้อความ: อบอุ่น ไม่ตัดสิน ไม่ต้องรู้คำตอบมาก่อน — เช่น
- หัวข้อหลัก: "ยังไม่รู้ว่าอยากทำอาชีพอะไร? เริ่มจากรู้จักตัวเอง"
- รอง: "ตอบคำถามเกี่ยวกับสิ่งที่คุณถนัด สิ่งที่ชอบ และนิสัยการทำงาน ระบบ ML จะเทียบกับ 910 อาชีพทุกสาย
  แล้วบอกว่าอาชีพไหนใกล้คุณ ขาดทักษะอะไร และควรเริ่มพัฒนาตรงไหน"
- ปุ่มหลัก: "เริ่มทำแบบประเมิน" → /assessment · ปุ่มรอง: "ดูตัวอย่างผลลัพธ์" → /careers (โหมดตัวอย่าง)
(ปรับคำได้ แต่ต้องคงความหมาย ห้ามสัญญาว่า "หางานได้แน่นอน" หรือ "แม่นยำ 100%")

ส่วนของหน้า (เรียงตามนี้)
1. Hero: หัวข้อ + ปุ่ม + ภาพตัวอย่างผลจริงจาก SAMPLE_RECOMMEND (การ์ด Top 5 ย่อ + radar เล็ก) แทนภาพประกอบ AI ทั่วไป
2. "ใช้เวลาประมาณ X นาที · 76 ข้อ · ไม่ต้องสมัครก็ลองได้" (คำนวณจากจำนวนคำถามจริง ห้ามเดา)
3. ใช้งานยังไง 3 ขั้น: รู้จักตัวเอง (แบบประเมิน 4 หมวด) → เจออาชีพที่ใกล้คุณ → รู้ว่าต้องพัฒนาอะไร (Skill Gap + Roadmap)
4. อาชีพทุกสาย: การ์ดกลุ่มอาชีพจาก SOC_MAJOR ใน lib/labels.ts (22 กลุ่มจริง) เลือกโชว์ ~8 กลุ่มที่หลากหลาย
   (การแพทย์ การศึกษา ช่าง/ซ่อมบำรุง การผลิต อาหาร/บริการ ขนส่ง ธุรกิจ/การเงิน ศิลปะ/สื่อ คอมพิวเตอร์) — ห้ามเอียงไปทาง IT
5. "เบื้องหลังคือ ML" — การ์ดโมเดลที่มีอยู่แล้ว (MODELS) ปรับดีไซน์ให้สวย และ **แก้ข้อมูลให้ตรงกับของจริง**:
   ① ใช้ Cosine Similarity (ไม่ใช่ centered — centered แพ้ในการทดสอบ) · ②a MLP (256) · ②b kNN (k=15) · ③ K-Means + PCA
   ตัวเลขความแม่น (ถ้าใส่) ต้องมาพร้อมคำว่า "ทดสอบกับผู้ใช้จำลอง" เช่น "Top-5 83.4% ในผู้ใช้จำลองที่ตอบคลาดเคลื่อน"
6. ความโปร่งใส: ข้อมูลอาชีพจาก O*NET (ตลาดแรงงานสหรัฐฯ) · ชื่ออาชีพไทยแปลโดย AI · ยังไม่ได้วัดกับคนจริง — การ์ดเล็ก ไม่ต้องเด่น
7. CTA ท้ายหน้า: "อนาคตเริ่มจากรู้จักตัวเอง" + ปุ่มเริ่มทำแบบประเมิน
8. Footer: ชื่อโปรเจกต์ ผู้จัดทำ ที่มาของข้อมูล (O*NET, NCES CIP–SOC) ลิงก์ไปหน้าหลัก

ดีไซน์: gradient อ่อนจาก primary-soft ที่ hero, การ์ดมี hover ยกตัวเล็กน้อย, fade-in ตอนเลื่อนลง (ปิดเมื่อ reduced-motion)
ห้ามมีข้อความรีวิวผู้ใช้ปลอม ตัวเลขผู้ใช้ปลอม หรือโลโก้บริษัทพันธมิตร
```

## P03 — ระบบสมาชิกจริง + โปรไฟล์ (ระยะ 3 — งาน backend ใหญ่)

```
[P00]

งาน: เปลี่ยน login/ประวัติ/ผลประเมินจาก localStorage เป็นระบบจริงตาม Tech stack ใน CLAUDE.md
(ทำหลังหน้าเว็บหลักเสร็จ — งานนี้เปลี่ยน backend เยอะ)

Backend
- PostgreSQL + pgvector ผ่าน docker-compose (ตาม CLAUDE.md หัวข้อ Database: schema 11 ตารางจาก careerpath-db
  และต้องแก้ careers.skill_vector เป็น vector(76))
- สมัคร/เข้าสู่ระบบ: รหัสผ่าน hash ด้วย argon2 หรือ bcrypt · JWT เก็บแค่ user_id · JWT_SECRET จาก env ห้าม commit
- endpoint: POST /api/auth/register, /api/auth/login, GET /api/me, PATCH /api/me,
  GET/POST /api/assessments (บันทึกคำตอบ + ผล recommend ที่ backend คำนวณ), GET /api/assessments/{id}
- ผลประเมินคำนวณที่ backend ด้วย CareerPredictor ตัวเดิมเท่านั้น — frontend ห้ามส่ง "ผล" มาบันทึกเอง
- เทสต์: สมัคร ล็อกอิน token หมดอายุ เข้าถึงข้อมูลคนอื่นไม่ได้

Frontend
- หน้า Login/Register เดิม (Login.tsx) ต่อกับ API จริง: validate, error ภาษาไทย, loading, "จดจำฉัน"
  (ลืมรหัสผ่าน: ถ้ายังไม่มีระบบส่งอีเมล ให้เขียนว่า "ยังไม่รองรับ" ไม่ทำปุ่มหลอก)
- Protected routes สำหรับหน้าที่ต้องมีบัญชี · ยังทำแบบประเมินโดยไม่สมัครได้ (ผลเก็บชั่วคราวในเครื่อง แล้วเสนอให้บันทึก)
- หน้าโปรไฟล์ (เข้าจากไอคอนผู้ใช้ ไม่ต้องเพิ่มในเมนูหลัก): ชื่อ อีเมล ระดับการศึกษา สาขาที่จบ (ใช้รายการจาก /api/majors)
  สถานะตอนนี้ (กำลังหางาน / ทำงานแล้วอยากเปลี่ยน / ยังเรียน) ประวัติการประเมิน
- ข้อมูลโปรไฟล์ **ไม่ใช่ input ของโมเดล** (ยกเว้นสาขาที่จบซึ่งใช้กับการ์ด "อาชีพในสายที่เรียนจบ" ที่มีอยู่แล้ว)
- ย้ายข้อมูลใน localStorage ของผู้ใช้เข้าบัญชีตอนล็อกอินครั้งแรก
```

## P04 — แบบประเมิน (ปรับ UX เท่านั้น — src/pages/Assessment.tsx)

```
[P00]

งาน: ทำให้แบบประเมิน 76 ข้อทำง่าย ไม่น่าเบื่อ ทำจนจบได้ — **ห้ามเพิ่ม/ลบ/แก้ข้อความคำถาม หรือเปลี่ยนสเกล 1–5**
(โมเดลเทรนกับ 76 ข้อนี้ ถ้าเปลี่ยนต้องเทรนใหม่)

1. Wizard ตาม 4 หมวดเดิม: ทักษะ 30 · ความสนใจ 6 · ลักษณะงานที่ชอบ 30 · นิสัย 10
   แสดงหมวดละหน้า (หรือแบ่งหน้าย่อยหน้าละ ~8 ข้อ) + แถบความคืบหน้ารวม และรายหมวด
2. ขั้นแรก (ไม่บังคับ ไม่เข้าโมเดล): สาขาที่จบ (MajorCard เดิม) + สถานะตอนนี้ — บอกชัด ๆ ว่า "ข้อมูลนี้ไม่ใช้คำนวณอาชีพ
   ใช้แค่แสดงอาชีพในสายที่เรียนมา"
3. ตัวเลือก 1–5 เป็นปุ่มใหญ่กดง่ายบนมือถือ มีคำกำกับปลายสเกลตาม questions.json · ใช้คีย์บอร์ด 1–5 ได้
4. บันทึกความคืบหน้าอัตโนมัติ (store เดิม) + "ทำต่อจากเดิม" เมื่อกลับมา
5. หน้าทบทวนก่อนส่ง: สรุปรายหมวด ข้อที่ยังไม่ตอบ (ระบบใช้ค่ากลางแทน — บอกผู้ใช้ตามจริง) ปุ่มย้อนแก้
6. ส่งแล้ว: เรียก recommend() เดิม → หน้า Careers พร้อม skeleton ระหว่างรอ
```

```
งาน: ทำหน้าผลลัพธ์ให้ดูเป็นผลิตภัณฑ์ AI ระดับมืออาชีพ และเพิ่มหน้ารายละเอียดอาชีพ โดยใช้ข้อมูลจริงจาก backend เท่านั้น

   reference_vectors.csv: ระดับที่ต้องการ 76 ข้อ; tools_reference.csv: เครื่องมือ; career_key_skills.csv ถ้ามี) + เทสต์
   แสดง: คำอธิบายงาน (O*NET ภาษาอังกฤษ — บอกว่ายังไม่ได้แปล) · ทักษะ 30 กลุ่มที่ต้องการ (เรียงจากมากไปน้อย)
```

## P06 — Skill Gap Dashboard (src/pages/SkillGap.tsx)

```
[P00]

งาน: ทำ Skill Gap ให้เห็นภาพชัด ข้อมูลทั้งหมดจาก skillGap() ของ backend (ผู้ใช้ vs ระดับที่อาชีพต้องการ ของ 30 กลุ่มทักษะ)

1. ตัวเลือกอาชีพ: Top 5 ของผู้ใช้ + อาชีพที่อยากเป็น (Goal) + ค้นหาจาก listCareers()
2. แถวสรุป (StatTile): ผ่านเกณฑ์ X/30 กลุ่ม · ทักษะครอบคลุม % · Gap รวม · เครื่องมือที่อาชีพนี้ใช้
3. Radar (SkillRadar เดิม): ผู้ใช้ vs อาชีพ — แสดงแค่ 8–10 กลุ่มที่ Gap/ความสำคัญสูงสุดให้อ่านออก + toggle "ดูทั้ง 30"
4. แบ่ง 3 กลุ่ม (คำนวณจากค่าที่ backend ส่งมา ไม่ใช่สูตรใหม่):
   - จุดแข็ง: gap = 0 (ถึงหรือเกินระดับที่ต้องการ)
   - ควรพัฒนา: 0 < gap ≤ 25
   - ยังขาด: gap > 25
   (เกณฑ์ 25 = 1 ระดับของสเกล 1–5 — เขียนบอกผู้ใช้ด้วย)
5. ลำดับความสำคัญ สูง/กลาง/ต่ำ: แบ่งจากค่า priority ของ backend (Skill Priority) เป็น 3 ช่วงตามอันดับ
   (1/3 แรก = สูง) — แสดงสูตรสั้น ๆ ในส่วนพับได้ "จัดลำดับยังไง": gap × (1 + 0.5·ความสำคัญ O*NET + 0.5·ความเฉพาะของอาชีพ)
6. แถบเทียบรายทักษะ (GapBar เดิม): ระดับปัจจุบัน / ระดับที่ต้องการ / ป้ายสถานะ / ลำดับความสำคัญ
   filter ตาม 3 กลุ่ม + เรียงตามความสำคัญหรือขนาด Gap · คลิกกราฟแล้วไฮไลต์แถวที่ตรงกัน (เชื่อมกัน)
7. ปุ่ม "สร้าง Roadmap จากทักษะเหล่านี้" → /roadmap
ห้ามใช้ชื่อทักษะสมมติ (Python, SQL…) — ใช้ชื่อกลุ่มทักษะภาษาไทยที่ backend ส่งมาเท่านั้น
```
